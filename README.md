# 물어봇 (Mureobot)

UI/UX 프로그래밍 · 2주차 과제
학교 생활이 낯선 신입생을 위한 학사 안내 챗봇 서비스 소개 페이지입니다.

배포 주소: `https://isanguk38.github.io/uiuxprogramming/`

## 1. 서비스 기획

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 물어봇 |
| 주요 사용자 | 학교 생활이 아직 낯선 1학년 신입생 |
| 해결하려는 문제 | 수강신청·서류 발급·시설 이용처럼 사소하지만 급한 질문을 어디에 물어야 할지 모른다. 공지사항은 흩어져 있고 학과 사무실은 정해진 시간에만 열린다. |

## 3. 구현하면서 바꾼 구조와 이유

수업 예제 구조를 기준으로, 실제 기획에 맞추기 위해 아래를 변경했습니다.

### 3-1. 입력 영역의 이름을 `소식 받기`에서 `사전 신청`으로 변경

핵심 행동이 "소식 구독"이 아니라 "정식 공개 전 사용 신청"이기 때문입니다. `h2`와 버튼 문구(`사전 신청하기`), `nav` 링크 텍스트를 함께 바꿔 사용자가 클릭 전후에 같은 단어를 보게 했습니다. 버튼이 하는 일과 버튼에 적힌 말이 어긋나지 않도록 하는 것이 목적입니다.

`id`는 `subscribe`를 그대로 두었습니다. 문서 안의 앵커 식별자라 표시 문구가 바뀌어도 연결이 유지되는 편이 안전하다고 판단했습니다.

### 3-2. `about` 영역의 본문을 문제 서술로 교체

예제의 한 줄 소개는 어떤 서비스에나 붙을 수 있는 문장이었습니다. 신입생이 실제로 겪는 상황(공지가 흩어져 있음, 사무실 운영 시간 제한)을 먼저 쓰고 서비스 정의를 뒤에 두어, 방문자가 "이게 내 문제인가"를 먼저 판단하도록 했습니다.

### 3-3. `features`를 `ul`, `steps`를 `ol`로 구분

기능 3개는 우열이나 순서가 없어 `ul`을, 이용 방법은 반드시 위에서부터 거쳐야 하는 흐름이라 `ol`을 썼습니다. 눈으로 보면 둘 다 목록이지만 스크린 리더는 `ol`에서 "1단계 중 3" 같은 위치 정보를 읽어 주기 때문에 의미가 다릅니다.

### 3-4. `img`의 `alt` 문장 수정

`로봇 이미지`처럼 파일이 무엇인지 설명하는 대신, 화면에서 그 이미지가 전달하는 인상(`웃는 얼굴로 인사하는 안내 챗봇 물어봇`)을 적었습니다.

### 3-5. `nav`에 `aria-label` 유지

페이지에 `nav`가 하나뿐이지만, 이후 주차에 푸터 메뉴가 추가될 것을 고려해 `주요 메뉴`라는 이름을 남겨 두었습니다.

# 3주차 CSS 수정 기록
## 4. 사전 신청 폼 스타일 수정

| `flex-wrap: wrap`, `flex: 0 0 100%`, `flex: 1`, `white-space: nowrap` | 이메일 라벨이 한 줄로 보이고, 입력창과 버튼이 나란히 같은 높이로 맞춰짐 | 사전 신청 폼을 읽고 입력하기 쉬워짐 |

`.email-field`에 `flex: 1`이 걸려 라벨 너비가 줄어들면서 "이메일"이 세로로 깨지고, 버튼 문구도 두 줄로 줄바꿈되었습니다. 라벨은 `flex: 0 0 100%`로 한 줄을 쓰고, 입력창에 `flex: 1`을 주어 남은 공간을 채우며, 버튼은 `white-space: nowrap`으로 한 줄을 유지하도록 바꿨습니다.

# 4주차 반응형 수정 기록

## 확인한 문제
미디어쿼리 선택자가 HTML 클래스와 맞지 않아(`.features-list` 등) 규칙이 적용되지 않았습니다.
390px·768px에서 메뉴·소개 영역·기능 카드·폼이 가로로 남아 내용이 좁고 가로 스크롤이 생겼습니다.
769px에서는 카드만 비좁게 한 줄로 붙어 있었습니다.

## 수정한 내용
`viewport`는 유지하고, 기능 카드를 `display: grid` + `auto-fit`으로 바꿨습니다.
768px 이하에서는 `.site-nav`·`.about-layout`·`.feature-list`·`.subscribe-form`을 한 열로 배치했습니다.
입력창·버튼은 `width: 100%`로 맞춰 터치하기 쉽게 했습니다.

## 달라진 점
1100px | 메뉴·카드·소개가 가로 배치되고 여백이 안정적이게 되었습니다.
769px | 카드가 칸 너비에 맞춰 자동으로 줄바꿈이 됩니다.
768px | 메뉴·소개·카드·폼이 한 열로 전환됩니다.
390px | 가로 스크롤 없이 읽고 이메일 신청이 가능합니다.

# 5주차 JavaScript로 값을 저장하고 결과 만들기

## 확인한 문제
사전 신청을 눌러도 안내 문구와 버튼이 그대로라, 신청이 처리됐는지 알기 어려웠습니다.

## 수정한 내용
`script.js`에서 신청 여부를 `isSubscribed`로 저장합니다.
제출하면 입력한 이메일이 들어간 완료 문구, `is-saved` 스타일, 버튼 문구(`신청 완료`)와 `disabled`를 함께 바꿉니다.

## 달라진 점
`learner@example.com`을 입력하면 "learner@example.com로 신청이 완료되었습니다."가 초록 배경으로 보이고, 버튼은 다시 누를 수 없는 완료 상태가 됩니다.

# 6주차 이벤트 처리와 동적 UI 구현

## 구현한 이벤트
| 이벤트 | 요소 | 화면 변화 |
| `click` | 테마 버튼 | `body`에 `dark` 클래스를 켜고 끄며 버튼 문구가 함께 바뀜 |
| `input` | 사용자 이름 입력창 | 입력하거나 지울 때마다 `0 / 10` 글자 수가 바뀜 |
| `change` | 이용 안내 체크박스 | 안내 문구, `is-ready` 스타일, 시작 버튼 `disabled`가 함께 바뀜 |
| `click` | 탭 3개 (서비스 소개 · 이용 방법 · 자주 묻는 질문) | 선택한 탭과 `data-target`으로 연결된 패널 하나만 보임 |

## 테스트 결과
| 확인 범위 | 조작 | 결과 |
| 이벤트 | 클릭·입력·체크를 각각 실행 | 테마 버튼, 이름 입력, 체크박스가 각자 연결된 부분만 바뀜. 이름에 "새내기" 입력하면 3 / 10으로 표시됨 |
| 상태 | 체크와 해제를 반복 | 체크하면 문구가 초록색으로 바뀌고 시작 버튼이 눌림. 해제하면 원래 문구와 회색 버튼으로 돌아옴 |
| 탭 | 세 탭을 차례로 선택 | 누른 탭만 밑줄이 생기고 패널도 하나만 보임. 두 개가 같이 보이는 경우는 없었음 |
| 반응형 | 1100px·768px·390px에서 확인 | 1100px은 탭이 가로 한 줄, 768px·390px은 세로로 쌓임. 세 크기 모두 가로 스크롤 없음 |
| 키보드 | Tab·Enter·Space로 조작 | Tab으로 탭 버튼 이동 후 Enter로 패널 전환됨. 테마 버튼과 체크박스도 Space로 동작함 |

## 테스트하면서 고친 부분
어두운 테마로 바꿨을 때 서비스 소개 카드, 탭 패널, 안내 확인 문구가 밝은 배경에 밝은 글자로 나와서 거의 안 보였습니다.
`body.dark` 선택자에 `.content-section`, `.panel`을 추가하고, `#agreeMessage`에는 글자색을 따로 지정해서 해결했습니다.

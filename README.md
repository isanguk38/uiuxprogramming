# 물어봇 (Mureobot)

UI/UX 프로그래밍 · 2주차 과제
학교 생활이 낯선 신입생을 위한 학사 안내 챗봇 서비스 소개 페이지입니다.

배포 주소: `https://isanguk38.github.io/uiuxprogramming/`

## 1. 서비스 기획

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 물어봇 |
| 주요 사용자 | 학교 생활이 아직 낯선 1학년 신입생 |
| 해결하려는 문제 | 수강신청·서류 발급·시설 이용처럼 사소하지만 급한 질문을 어디에 물어야 할지 모른다. 공지사항은 흩어져 있고 학과 사무실은 정해진 시간에만 열린다. |
| 핵심 행동 | 서비스 내용을 확인하고 이메일로 사전 사용을 신청한다 |
| 정보 순서 | 서비스 소개 → 주요 기능 → 이용 방법 → 사전 신청 |

이 내용은 `index.html`의 `<body>` 첫 줄 주석과 동일하게 유지했습니다.


| 영역 | id | 요소 | 역할 |
| --- | --- | --- | --- |
| 서비스 소개 | `about` | `section` + `img` | 서비스 정의와 해결하려는 문제 |
| 주요 기능 | `features` | `ul` > `li` | 순서 없는 기능 3개 |

`header`의 `nav` 링크 네 개가 각각 위 `id`로 이동합니다.

## 3. 구현하면서 바꾼 구조와 이유

수업 예제 구조를 기준으로, 실제 기획에 맞추기 위해 아래를 변경했습니다.

### 3-1. 입력 영역의 이름을 `소식 받기`에서 `사전 신청`으로 변경

핵심 행동이 "소식 구독"이 아니라 "정식 공개 전 사용 신청"이기 때문입니다. `h2`와 버튼 문구(`사전 신청하기`), `nav` 링크 텍스트를 함께 바꿔 사용자가 클릭 전후에 같은 단어를 보게 했습니다. 버튼이 하는 일과 버튼에 적힌 말이 어긋나지 않도록 하는 것이 목적입니다.

`id`는 `subscribe`를 그대로 두었습니다. 문서 안의 앵커 식별자라 표시 문구가 바뀌어도 연결이 유지되는 편이 안전하다고 판단했습니다.

### 3-2. `about` 영역의 본문을 문제 서술로 교체

예제의 한 줄 소개는 어떤 서비스에나 붙을 수 있는 문장이었습니다. 신입생이 실제로 겪는 상황(공지가 흩어져 있음, 사무실 운영 시간 제한)을 먼저 쓰고 서비스 정의를 뒤에 두어, 방문자가 "이게 내 문제인가"를 먼저 판단하도록 했습니다.

### 3-3. `features`를 `ul`, `steps`를 `ol`로 구분

기능 3개는 우열이나 순서가 없어 `ul`을, 이용 방법은 반드시 위에서부터 거쳐야 하는 흐름이라 `ol`을 썼습니다. 눈으로 보면 둘 다 목록이지만 스크린 리더는 `ol`에서 "1단계 중 3" 같은 위치 정보를 읽어 주기 때문에 의미가 다릅니다.

### 3-4. `img`의 `alt` 문장 수정

`로봇 이미지`처럼 파일이 무엇인지 설명하는 대신, 화면에서 그 이미지가 전달하는 인상(`웃는 얼굴로 인사하는 안내 챗봇 물어봇`)을 적었습니다.

### 3-5. `nav`에 `aria-label` 유지

페이지에 `nav`가 하나뿐이지만, 이후 주차에 푸터 메뉴가 추가될 것을 고려해 `주요 메뉴`라는 이름을 남겨 두었습니다.

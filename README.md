# 물어봇 (Mureobot)

UI/UX 프로그래밍 · 2주차 과제
학교 생활이 낯선 신입생을 위한 학사 안내 챗봇 서비스 소개 페이지입니다.

배포 주소: `https://isanguk38.github.io/uiuxprogramming/`

## 1. 서비스 기획

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 물어봇 |
| 주요 사용자 | 학교 생활이 아직 낯선 1학년 신입생 |
| 해결하려는 문제 | 수강신청·서류 발급·시설 이용처럼 사소하지만 급한 질문을 어디에 물어야 할지 모른다. 공지사항은 흩어져 있고 학과 사무실은 정해진 시간에만 열린다. |

## 3. 구현하면서 바꾼 구조와 이유

수업 예제 구조를 기준으로, 실제 기획에 맞추기 위해 아래를 변경했습니다.

### 3-1. 입력 영역의 이름을 `소식 받기`에서 `사전 신청`으로 변경

핵심 행동이 "소식 구독"이 아니라 "정식 공개 전 사용 신청"이기 때문입니다. `h2`와 버튼 문구(`사전 신청하기`), `nav` 링크 텍스트를 함께 바꿔 사용자가 클릭 전후에 같은 단어를 보게 했습니다. 버튼이 하는 일과 버튼에 적힌 말이 어긋나지 않도록 하는 것이 목적입니다.

`id`는 `subscribe`를 그대로 두었습니다. 문서 안의 앵커 식별자라 표시 문구가 바뀌어도 연결이 유지되는 편이 안전하다고 판단했습니다.

### 3-2. `about` 영역의 본문을 문제 서술로 교체

예제의 한 줄 소개는 어떤 서비스에나 붙을 수 있는 문장이었습니다. 신입생이 실제로 겪는 상황(공지가 흩어져 있음, 사무실 운영 시간 제한)을 먼저 쓰고 서비스 정의를 뒤에 두어, 방문자가 "이게 내 문제인가"를 먼저 판단하도록 했습니다.

### 3-3. `features`를 `ul`, `steps`를 `ol`로 구분

기능 3개는 우열이나 순서가 없어 `ul`을, 이용 방법은 반드시 위에서부터 거쳐야 하는 흐름이라 `ol`을 썼습니다. 눈으로 보면 둘 다 목록이지만 스크린 리더는 `ol`에서 "1단계 중 3" 같은 위치 정보를 읽어 주기 때문에 의미가 다릅니다.

### 3-4. `img`의 `alt` 문장 수정

`로봇 이미지`처럼 파일이 무엇인지 설명하는 대신, 화면에서 그 이미지가 전달하는 인상(`웃는 얼굴로 인사하는 안내 챗봇 물어봇`)을 적었습니다.

### 3-5. `nav`에 `aria-label` 유지

페이지에 `nav`가 하나뿐이지만, 이후 주차에 푸터 메뉴가 추가될 것을 고려해 `주요 메뉴`라는 이름을 남겨 두었습니다.

# 3주차 CSS 수정 기록
## 4. 사전 신청 폼 스타일 수정

| `flex-wrap: wrap`, `flex: 0 0 100%`, `flex: 1`, `white-space: nowrap` | 이메일 라벨이 한 줄로 보이고, 입력창과 버튼이 나란히 같은 높이로 맞춰짐 | 사전 신청 폼을 읽고 입력하기 쉬워짐 |

`.email-field`에 `flex: 1`이 걸려 라벨 너비가 줄어들면서 "이메일"이 세로로 깨지고, 버튼 문구도 두 줄로 줄바꿈되었습니다. 라벨은 `flex: 0 0 100%`로 한 줄을 쓰고, 입력창에 `flex: 1`을 주어 남은 공간을 채우며, 버튼은 `white-space: nowrap`으로 한 줄을 유지하도록 바꿨습니다.

# 4주차 반응형 수정 기록

## 확인한 문제
미디어쿼리 선택자가 HTML 클래스와 맞지 않아(`.features-list` 등) 규칙이 적용되지 않았습니다.
390px·768px에서 메뉴·소개 영역·기능 카드·폼이 가로로 남아 내용이 좁고 가로 스크롤이 생겼습니다.
769px에서는 카드만 비좁게 한 줄로 붙어 있었습니다.

## 수정한 내용
`viewport`는 유지하고, 기능 카드를 `display: grid` + `auto-fit`으로 바꿨습니다.
768px 이하에서는 `.site-nav`·`.about-layout`·`.feature-list`·`.subscribe-form`을 한 열로 배치했습니다.
입력창·버튼은 `width: 100%`로 맞춰 터치하기 쉽게 했습니다.

## 달라진 점
1100px | 메뉴·카드·소개가 가로 배치되고 여백이 안정적이게 되었습니다.
769px | 카드가 칸 너비에 맞춰 자동으로 줄바꿈이 됩니다.
768px | 메뉴·소개·카드·폼이 한 열로 전환됩니다.
390px | 가로 스크롤 없이 읽고 이메일 신청이 가능합니다.

# 5주차 JavaScript로 값을 저장하고 결과 만들기

## 확인한 문제
사전 신청을 눌러도 안내 문구와 버튼이 그대로라, 신청이 처리됐는지 알기 어려웠습니다.

## 수정한 내용
`script.js`에서 신청 여부를 `isSubscribed`로 저장합니다.
제출하면 입력한 이메일이 들어간 완료 문구, `is-saved` 스타일, 버튼 문구(`신청 완료`)와 `disabled`를 함께 바꿉니다.

## 달라진 점
`learner@example.com`을 입력하면 "learner@example.com로 신청이 완료되었습니다."가 초록 배경으로 보이고, 버튼은 다시 누를 수 없는 완료 상태가 됩니다.

# 6주차 이벤트 처리와 동적 UI 구현

## 구현한 이벤트
| 이벤트 | 요소 | 화면 변화 |
| `click` | 테마 버튼 | `body`에 `dark` 클래스를 켜고 끄며 버튼 문구가 함께 바뀜 |
| `input` | 사용자 이름 입력창 | 입력하거나 지울 때마다 `0 / 10` 글자 수가 바뀜 |
| `change` | 이용 안내 체크박스 | 안내 문구, `is-ready` 스타일, 시작 버튼 `disabled`가 함께 바뀜 |
| `click` | 탭 3개 (서비스 소개 · 이용 방법 · 자주 묻는 질문) | 선택한 탭과 `data-target`으로 연결된 패널 하나만 보임 |

## 테스트 결과
| 확인 범위 | 조작 | 결과 |
| 이벤트 | 클릭·입력·체크를 각각 실행 | 테마 버튼, 이름 입력, 체크박스가 각자 연결된 부분만 바뀜. 이름에 "새내기" 입력하면 3 / 10으로 표시됨 |
| 상태 | 체크와 해제를 반복 | 체크하면 문구가 초록색으로 바뀌고 시작 버튼이 눌림. 해제하면 원래 문구와 회색 버튼으로 돌아옴 |
| 탭 | 세 탭을 차례로 선택 | 누른 탭만 밑줄이 생기고 패널도 하나만 보임. 두 개가 같이 보이는 경우는 없었음 |
| 반응형 | 1100px·768px·390px에서 확인 | 1100px은 탭이 가로 한 줄, 768px·390px은 세로로 쌓임. 세 크기 모두 가로 스크롤 없음 |
| 키보드 | Tab·Enter·Space로 조작 | Tab으로 탭 버튼 이동 후 Enter로 패널 전환됨. 테마 버튼과 체크박스도 Space로 동작함 |

## 테스트하면서 고친 부분
어두운 테마로 바꿨을 때 서비스 소개 카드, 탭 패널, 안내 확인 문구가 밝은 배경에 밝은 글자로 나와서 거의 안 보였습니다.
`body.dark` 선택자에 `.content-section`, `.panel`을 추가하고, `#agreeMessage`에는 글자색을 따로 지정해서 해결했습니다.

# 7주차 사용자 흐름과 인터랙션 시나리오 설계

## 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 물어봇 |
| 주요 사용자 | 학교 생활이 아직 낯선 1학년 신입생 |
| 서비스 목적 | 수강신청·서류 발급·시설 이용처럼 사소하지만 급한 질문을 어디에 물어야 할지 모르는 문제를 해결한다. 학교 공지와 학사 규정에서 근거를 찾아 답하고, 더 확인할 내용은 담당 부서로 연결한다. |
| 완료할 핵심 행동 | 이용 안내를 확인하고 물어봇에게 질문을 남겨 담당 부서 안내를 받는다. |
| 완료 조건 | 확인 화면에서 이름·질문 분야·궁금한 점을 검토하고 **'질문이 접수되었습니다'** 화면에 도달한다. |

페이지 구성: 서비스 소개 → 서비스 정보(탭) → 물어봇 이용 설정 → **물어봇에게 질문하기(7주차)** → 이용 방법 → 사전 신청

---

## 사용자 흐름

```
[이용 안내 확인 체크] → [물어봇 시작하기]
        ↓
1. 질문 작성 (이름 · 궁금한 점)  ──빈 값──▶ 같은 단계에서 오류 안내 후 수정
        ↓ 분야 선택하기
2. 분야 선택 (수강신청·학사 / 증명서·서류 / 시설 이용 / 기타)
        │  ──분야 미선택──▶ 같은 단계에서 오류 안내 후 수정
        │  ──'기타' 선택──▶ 담당 부서 연결 안내 표시
        │  ◀── 질문 수정하기 (값 유지)
        ↓ 내용 확인하기
3. 내용 확인 (이름 · 분야 · 질문 요약)
        │  ◀── 분야 수정하기 (값 유지, 고친 값이 다시 반영됨)
        ↓ 질문 보내기
4. 접수 완료 (답변·담당 부서 연결 안내)
        ↓ 다시 질문하기
   입력·선택·오류·요약·진행 상태 초기화 → 1단계
```

- **진입**: 6주차의 기존 조건(이용 안내 체크 → 시작 버튼 활성화)을 그대로 두고, 체크된 상태에서 `물어봇 시작하기`를 눌러야만 질문 흐름이 열립니다.
- 진행 상태는 `1 / 3 · 질문 작성`처럼 화면 상단에 표시되고 `aria-live`로 읽힙니다.

## 인터랙션 시나리오

| 행동 | 이벤트 · 조건 | 화면 반응과 다음 상태 |
| --- | --- | --- |
| 안내 확인 없이 시작 시도 | `change` · 체크 해제 | 시작 버튼이 `disabled`라 흐름이 열리지 않음 (6주차 동작 유지) |
| 안내 확인 후 시작 | `click` · 체크됨 | 질문 영역이 나타나고 1단계로 스크롤·포커스 이동 |
| 이름·질문 없이 다음 | `click` · 이름 또는 질문 빈 값 | 비어 있는 항목과 입력 방법을 오류 문구로 표시, 해당 칸 빨간 테두리, 첫 오류 칸에 포커스, 1단계 유지 |
| 오류 칸을 다시 입력 | `input` | 해당 칸의 오류 테두리 제거 |
| 분야 없이 다음 | `click` · 분야 빈 값 | "질문 분야를 선택해 주세요. 잘 모르겠다면 '기타'를 고르면 됩니다." 표시, 2단계 유지 |
| 분야를 '기타'로 변경 | `change` · 값이 '기타' | 담당 부서 연결 안내 표시 (다른 분야로 바꾸면 숨김) |
| 2단계에서 질문 수정하기 | `click` · 수정 요청 | 입력값 유지한 채 1단계로 이동 |
| 3단계에서 분야 수정하기 | `click` · 수정 요청 | 선택값 유지한 채 2단계로 이동, 다시 확인하면 고친 값이 요약에 반영 |
| 질문 보내기 | `click` | 접수 완료 화면 표시, 진행 상태 `접수 완료` |
| 다시 질문하기 | `click` · 초기화 | 이름·질문·분야·'기타' 안내·오류·요약·진행 상태를 초기화하고 1단계로 이동 |

입력창마다 항상 보이는 `<label>`을 두었고, 오류 문구는 `role="alert"`와 `aria-describedby`로 입력창과 연결했습니다.

| 분야 미선택 | 2단계에서 바로 `내용 확인하기` | 분야 선택 안내 문구 표시, 2단계 유지 |
| 조건부 안내 | 분야를 '기타' → '수강신청·학사'로 변경 | '기타'일 때만 담당 부서 연결 안내가 보임 |
| 이전·수정 | 3단계 `분야 수정하기` → 2단계 `질문 수정하기` | 분야('기타')·질문 값이 그대로 남아 있음. 질문을 "휴학 신청은 어디서 하나요?"로, 분야를 '수강신청·학사'로 고치자 확인 화면에 고친 값이 반영됨 |
| 다시 시작 | 완료 화면에서 `다시 질문하기` | 이름·질문·분야·오류·요약이 모두 비워지고 `1 / 3 · 질문 작성`으로 돌아옴 |
| 모바일 | 390px에서 전 단계 조작 | 레이블·입력창·오류 문구가 잘리지 않고, 버튼은 전체 너비(48px 높이)로 쌓임. 확인 요약은 한 열로 표시. 가로 스크롤 없음 |
| 다크 테마 | 테마 버튼 후 질문 흐름 진행 | 단계 카드·입력창·요약 글자가 어두운 배경에서 읽힘 |
| 콘솔 | 개발자 도구 콘솔 확인 | 오류 없음 |

# 중간고사 응용 구현 — 내 질문 목록과 접수 취소
# 배포 주소 : 
	1. https://github.com/isanguk38/uiuxprogramming.git
	2. https://isanguk38.github.io/uiuxprogramming/
## 새로 추가한 것

7주차 '물어봇에게 질문하기' 흐름의 끝(질문 보내기)에 이어서, 접수한 질문이 **내 질문 목록**에 쌓이고 필요 없어진 질문은 **접수 취소**로 상태를 바꿀 수 있도록 했습니다.
신입생이 자신이 무엇을 물어봤는지 다시 확인하고, 이미 해결된 질문은 직접 정리할 수 있습니다.

## 연결 지점

```
질문 작성 → 분야 선택 → 내용 확인 → [질문 보내기] → 접수 완료
                                         │
                                         ▼
                              내 질문 목록에 '접수됨'으로 추가
                                         │ [접수 취소]
                                         ▼
                         확인 창 ─ 확인 → '취소됨'으로 변경
                                 └ 취소 → '접수됨' 유지
```

## 사용자 행동 → 조건 → 반응 → 다음 행동

| 사용자 행동 | 확인할 조건 | 성공 반응 | 다른 분기의 반응 | 다음 행동 |
| --- | --- | --- | --- | --- |
| 페이지에 들어와 내 질문 목록을 봄 | 접수한 질문이 있는가 | 접수한 질문 카드(상태·분야·질문·이름)를 보여 줌 | **결과 없음**: "아직 접수한 질문이 없습니다…" 안내와 `질문하러 가기` 버튼 표시 | `질문하러 가기`로 이용 설정 영역으로 이동해 질문 시작 |
| 7주차 흐름에서 `질문 보내기` | 확인 단계까지 이름·질문·분야가 입력됨 (7주차 검사 통과) | 목록에 '접수됨' 질문 추가, "질문이 내 질문 목록에 추가되었습니다." 표시 | — | `다시 질문하기`로 새 질문 접수 (목록은 유지) |
| 목록에서 `접수 취소` | 상태가 '접수됨'인 질문인가 → 확인 창에서 확인을 눌렀는가 | 상태가 '취소됨'(회색, 질문에 취소선)으로 바뀌고 취소 버튼이 사라짐, "질문 접수를 취소했습니다…" 표시 | **취소**: 확인 창에서 취소를 누르면 상태가 바뀌지 않고 "접수를 유지했습니다…" 표시 | 다시 궁금해지면 새 질문을 접수 |

## 구현 내용

| 파일 | 추가 내용 |
| --- | --- |
| `index.html` | 질문하기 영역 아래에 `#myQuestions`(안내 문구, 빈 목록 안내, `ul` 목록) 추가. 접수 완료 화면에 목록 안내 문구 한 줄 추가 |
| `style.css` | 목록 카드, 상태 표시(접수됨·취소됨), 빈 목록, 다크 테마, 768px 이하 한 열·전체 너비 버튼 규칙 추가 |
